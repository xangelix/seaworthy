# scripts/check-tls-construction.sh allowlist.
#
# Every TLS configuration is built in crates/seaworthy-crypto, and every
# outbound HTTP client takes a configuration built there. An entry here is a
# reviewed exception with its reason; an entry that matches nothing fails.
#
#   site <path> | <fragment of the matched line> | <reason>
#   path <prefix> | <reason>
#
site crates/seaworthy-updater/src/net.rs | use rustls_platform_verifier::BuilderVerifierExt as _; | the update helper attaches the OS trust store to the builder from seaworthy_crypto::tls::client_config_builder() (provider and policy stay the crypto crate's); keeping rustls-platform-verifier out of seaworthy-crypto spares its other users that dependency
site crates/seaworthy-updater/src/net.rs | .and_then(|builder| builder.with_platform_verifier()) | the same call: the verifier goes onto the crypto crate's canonical client builder, nothing else is configured here
site crates/seaworthy/src/s3/mod.rs | use rustls_platform_verifier::BuilderVerifierExt as _; | the S3 publish client attaches the OS trust store to the builder from seaworthy_crypto::tls::client_config_builder() (provider and policy stay the crypto crate's), as the update helper does
site crates/seaworthy/src/s3/mod.rs | .and_then(|builder| builder.with_platform_verifier()) | the same call: the verifier goes onto the crypto crate's canonical client builder, nothing else is configured here
site crates/seaworthy-lab/src/tls.rs | rustls::ServerConfig::builder_with_provider(seaworthy_crypto::tls_provider()) | the lab server (an unpublished test harness; seaworthy ships no TLS server, so seaworthy-crypto has no server builder): built on seaworthy-crypto's provider and protocol versions, so it negotiates only what the TLS policy permits, with one certificate chain and no client authentication
site crates/seaworthy-lab/src/client.rs | use rustls_platform_verifier::BuilderVerifierExt as _; | the lab's required-version client attaches the OS trust store to the builder from seaworthy_crypto::tls::client_config_builder() (provider and policy stay the crypto crate's), as the update helper does
site crates/seaworthy-lab/src/client.rs | .and_then(|builder| builder.with_platform_verifier()) | the same call: the verifier goes onto the crypto crate's canonical client builder, nothing else is configured here
